# 音澜（Melody Local）

一个使用 Kotlin 与 Jetpack Compose 编写的原生 Android 本地音乐播放器。歌曲、视频音轨提取和歌单操作以设备本地处理为主；歌词优先使用本地文件或歌曲内嵌标签，也可由用户主动通过 LRCLIB 搜索。

当前版本：`1.4.0`（Android `versionCode` 6）。本版本增加本地与在线歌词发现、逐字和多语歌词、歌词编辑、悬浮/系统歌词，以及按音频输出路由校准的显示延迟。

[下载已发布版本（可能落后于源码）](https://github.com/nishijie6/melody-local/releases/latest) · [隐私说明](PRIVACY.md) · [变更记录](CHANGELOG.md)

## 已实现功能

- 通过 `MediaStore` 扫描设备本地歌曲，支持 Android 8.0–16
- 按标题、歌手或最近添加排序，并支持歌名/歌手/专辑搜索
- 基于 Media3 ExoPlayer 的后台播放、系统媒体通知与耳机控制
- 播放/暂停、上一首、下一首与进度拖动
- 五种互斥播放模式：播放一次、列表循环、随机循环、单曲循环、倒序循环
- 随机播放使用 Media3 的随机遍历顺序，每轮每首歌曲只出现一次，上一首会沿当前随机顺序回退
- 倒序播放会从当前列表末尾向前循环；切换模式时保留当前歌曲和播放进度
- 切换顺序、列表循环、单曲循环和倒序模式仅更新播放器遍历策略；随机顺序在后台线程生成，切换时不阻塞界面、唱片动画或播放进度
- 全屏播放器提供明确的停止入口，可停止播放并清空当前队列
- 自动记住上次选择的播放模式
- 迷你播放器与沉浸式全屏播放页
- 全局使用暖白背景、白色卡片和珊瑚色强调的明亮主题，状态栏与导航栏图标保持深色高对比
- 黑胶唱片式旋转封面：播放时匀速旋转，暂停时停在当前角度并在恢复后续转
- 唱针随播放状态自动落下和抬起
- 创建、重命名、删除歌单；向歌单添加或移除歌曲；歌单名称不允许重复
- 使用 Room 在本机持久化歌单
- 歌词按本地优先顺序自动发现：先查询歌曲同目录的 MediaStore LRC 和用户明确授权目录中的同名歌词，再读取歌曲内嵌歌词标签；匹配成功后保存到应用私有目录
- 支持 ID3v2 `USLT`/`SYLT`/歌词类 `TXXX`、FLAC Vorbis Comment 和 MP4/M4A `©lyr`/歌词类 freeform 标签
- 可手动搜索并下载 [LRCLIB](https://lrclib.net) 歌词；自动在线匹配默认关闭，只有用户在歌词设置中主动开启后才会在本地来源无结果时联网
- 导入或显示 LRC 时支持多时间标签、`offset`、增强 LRC 逐字时间、原文/翻译/罗马音多层歌词、纯文本、UTF-8 和 GB18030；歌词随进度滚动，逐行或逐字高亮，点击行可跳转
- 内置 LRC 内容和时间轴编辑：插入当前播放时间、整体按毫秒平移时间标签并原子保存；仍可通过系统文件选择器导入或更换歌词
- 可选的可拖动桌面悬浮歌词，以及通知和锁屏媒体卡当前歌词；悬浮窗和通知均遵循 Android 系统授权，具体锁屏布局受系统及厂商界面影响
- 通过 Android 公开 API 识别扬声器、有线、传统蓝牙、蓝牙 LE、USB 和 HDMI 输出路由，并使用保守的歌词延迟估算；每种路由可在 `-5000…5000 ms` 内单独手动微调
- 通过系统文件选择器选择一个普通、未加密的本地视频，把其中音轨导出为 M4A：AAC 自动直封装，其他设备可解码音轨转为 AAC
- 导入视频前可编辑标题、歌手和专辑；默认把第一个可解码视频帧压缩为唱片封面，失败时使用原有占位封面
- 导出歌曲写入公共 `Music/音澜/视频提取/`，同名文件自动追加 `(2)`、`(3)`，不会覆盖已有文件
- 在歌单页把所有歌单歌曲按 MediaStore ID 去重后真正移动到 `Music/音澜/歌单汇总/`；最后一级目录名可修改
- 同卷歌曲优先保留 MediaStore ID；跨卷歌曲在 SHA-256 和大小校验通过后才删除源文件，并自动重映射所有歌单、歌词、封面和自定义元数据
- 文件移动带持久化事务日志、进度、取消、Android 系统授权等待态与部分完成摘要；进程中断后会续传已验证的本应用 pending 目标、重新请求删除授权，或完成已删除源文件的映射
- 启动恢复尚未运行时即使用户先点击汇总，也会在同一互斥区内先接管持久化旧任务，不会为同一批歌曲创建第二个操作或目标副本；多个历史任务按创建时间与 ID 稳定顺序逐个恢复

## 隐私

音澜不包含账号、广告、分析或遥测功能。网络权限只用于用户手动发起或明确开启的 LRCLIB 歌词匹配；自动在线匹配默认关闭，本地音频和已有歌词不会上传。视频和额外歌词目录只在用户通过 Android 系统选择器明确授权后读取；应用不会扫描 B 站或其他应用的私有缓存，不绕过沙箱、缓存加密或 DRM。由于 MediaStore ID 不能安全跨设备复用，应用数据不会进入 Android 云备份或设备迁移，详情见 [PRIVACY.md](PRIVACY.md)。

## 安装

1. 从 [GitHub Releases](https://github.com/nishijie6/melody-local/releases/latest) 下载已经公开发布的 `yinlan-*-release.apk`；发布页版本可能落后于仓库源码。本项目维护者本地生成的签名 APK 不提交到源码仓库。
2. 在 Android 设备上允许从当前来源安装应用。
3. 安装后授予音乐读取权限；Android 13 及以上还可授予通知权限，以显示后台播放控制。

## 使用歌词

1. 开始播放一首歌曲，点击底部迷你播放器，并在全屏播放页切换到“歌词”。
2. 当前歌曲还没有歌词时，应用会先尝试 MediaStore 可见的同目录 LRC、已授权歌词目录和歌曲内嵌标签。部分设备不会把 LRC 建立到 MediaStore；此时可从歌词设置选择歌曲所在目录，应用只扫描该授权目录的直接子项。
3. 仍未找到时，可从歌词菜单手动在线搜索 LRCLIB，或继续使用“导入 LRC”。自动在线匹配需要在设置中单独开启，默认不会联网。
4. 从歌词菜单可编辑原始 LRC、插入当前时间、整体平移时间轴、替换或移除歌词；也可开启悬浮歌词、通知歌词及输出延迟校准。锁屏媒体卡会收到同一份歌词元数据，但旧版系统是否显示由设备厂商决定。

无论来自手动导入、同目录匹配、内嵌标签还是 LRCLIB，应用采用的歌词都会保存到私有 `lyrics/` 目录，因此原始 LRC 被移动后仍可继续显示。手动在线搜索会显示候选及匹配度，由用户选择后才保存；已有本地歌词不会被自动在线结果覆盖。用户主动移除某首歌的歌词后，应用会暂停该歌曲的后台自动发现，避免内嵌或在线歌词立即被重新写回；再次执行自动匹配、导入、编辑或选择在线结果会恢复发现并保存新歌词。

常见的同步歌词格式：

```text
[ar:歌手]
[ti:歌名]
[00:12.40]第一句歌词
[00:18.75]第二句歌词
```

增强 LRC 可使用尖括号时间标签实现逐字高亮；同一行时间下可用显式层标记，或按原文、罗马音、翻译的顺序提供多行：

```text
[00:12.40]<00:12.40>你<00:12.70>好
[00:12.40][romanization]Ni hao
[00:12.40][translation]Hello
```

蓝牙补偿不是对设备真实音频链路的测量。Android 公开 API 只提供输出设备类型，因此音澜按路由使用保守估算，并把每种路由的手动微调保存在本机；耳机、编码器和厂商实现不同时，应以实际听感校准。

## 从视频提取歌曲

1. 在“歌曲”页点击右上角的视频图标，并通过 Android 系统文件选择器选取一个你有权使用的本地视频。
2. 编辑标题、歌手、专辑，并选择是否使用视频首帧作为封面。
3. 点击“开始提取”。任务可在前台进度窗口或系统通知中取消；成功后歌曲位于 `Music/音澜/视频提取/`。

音澜只处理系统选择器可访问的普通文件。无音轨、DRM、不可访问、设备无法解码或空间不足会明确失败，并清理临时文件和未发布的 MediaStore 项目。

## 汇总所有歌单歌曲

1. 打开“歌单”页右上角批量菜单，选择“汇总歌单歌曲”。
2. 确认去重后的歌曲数、总大小和目标文件夹名称。
3. 阅读“原位置将不再保留”警告后确认移动，并按系统提示授权。

Android 10 会逐首请求授权；Android 11–16 最多每 2000 首组成一个系统授权批次；Android 8–9 只在开始移动时请求旧版存储写入权限。进程在“已复制、待删除授权”时中断，下次会重新请求授权；用户可通过现有取消入口明确终止旧任务，不会阻塞下一次汇总。拒绝或取消不会撤销已成功完成的歌曲。Android 8–9 删除前会把源路径无覆盖隔离到本次操作专用路径，且验证临时副本一直保留到目标复验与关联提交完成。已经通过大小和 SHA-256 校验的目标副本不会仅凭一次“源仍存在”检查而删除：现代 Android 的隐藏完整副本会精确发布并保留，旧版完整目标也会保留；取消意图会先持久化，避免崩溃恢复后反向继续删除源文件。

安全限制：当前歌单、歌词和自定义元数据仍以数字 MediaStore ID 为键，并未迁移为“存储卷 + ID”复合键。同一个数字 ID 如果在多个当前具体存储卷上都有候选，或任一应查询存储卷暂时不可访问，该歌曲会明确失败且不会读写、删除或重映射；跨卷复制产生的新 ID 在提交关联前也必须在所有当前卷中唯一。Android 10 无法确认已物理拔出存储卷的历史身份，因此旧版本遗留的 `content://media/external/...` 合成 URI 不会被自动猜测升级；在该系统上，已拔卷歌曲与当前卷同 ID 的历史歧义无法自动修复。恢复日志会保留，其他身份明确的歌曲仍可正常处理。

## 构建

环境要求：JDK 17 或更高版本、Android SDK 36。

Windows Debug 构建：

```powershell
.\gradlew.bat assembleDebug
```

Windows Release 构建：

```powershell
.\gradlew.bat assembleRelease
```

macOS / Linux：

```bash
./gradlew assembleDebug
```

生成的 APK 位于：

```text
app/build/outputs/apk/debug/app-debug.apk
app/build/outputs/apk/release/app-release.apk          # 配置本地签名时
app/build/outputs/apk/release/app-release-unsigned.apk # 未配置签名时
```

Release 变体启用了 R8 代码压缩和资源裁剪。公开仓库不包含 Release 私钥或密码；维护者可复制 `keystore.properties.example` 为 `keystore.properties`，并把私钥放在本机的 `release-signing/` 目录。两者均已加入 `.gitignore`。请离线备份正式证书，否则未来无法覆盖安装使用该证书签名的版本。

## 工程结构

```text
app/src/main/java/com/melody/local/
├── data/       # MediaStore 曲库、Room 歌单数据库
├── lyrics/     # 本地/内嵌/在线歌词发现、LRC 解析与私有存储
├── media/      # 视频音轨导入、MediaStore 文件移动与恢复状态机
├── playback/   # Media3 播放服务与控制连接
├── systemlyrics/ # 悬浮/系统歌词、输出路由与延迟策略
├── ui/         # Compose 页面、组件和 ViewModel
└── MainActivity.kt
```

## 验证

```powershell
.\gradlew.bat testReleaseUnitTest lintRelease assembleRelease assembleDebugAndroidTest
```

连接模拟器或真机后运行 Android 集成测试：

```powershell
.\gradlew.bat connectedDebugAndroidTest
```

当前工程包含 196 项自动化测试：94 项 JVM 单元测试覆盖 LRC/增强 LRC、多语分层、ID3/FLAC/MP4 内嵌标签、同目录及 LRCLIB 匹配、歌词编辑、输出路由与延迟策略，以及播放、歌单和媒体操作恢复规则；102 项 Android 集成测试覆盖歌词持久化、授权目录真实文件名匹配、系统歌词元数据、具体 MediaStore 卷、真实歌曲移动与恢复、Media3、Room 迁移、ViewModel 竞态，以及 AAC 直封装和非 AAC 转码。CI 在 API 26、29、36 模拟器执行设备测试；API 29 与 36 作业要求可写的第二存储卷，若未正确挂载会直接失败，避免跨卷用例被静默跳过。
